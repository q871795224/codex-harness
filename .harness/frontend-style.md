# 前端样式约束

本文约束几个**固定 UI 区域**的样式写法。在这些区域新增元素时，必须复用既有结构、共用选择器组和主题变量，不要自行新起一套字号、padding、颜色或一次性微调。只记录稳定约定；具体视觉数值以 `src/styles.css` 为准，本文不复制数值。

## 总原则

- **同区域、同类型的元素进同一个共用选择器组**，不为新元素单独写一份重复规则。
- **深色主题必须成对覆盖**：改了 `background`/`border-color` 就必须同时确认 `color`（文字/图标）在深色下也被显式覆盖，不能让它回落到为浅色设计的基色。漏配 `color` 会导致深色背景叠近黑文字。
- **新颜色优先用已有的主题变量/色板**，不引入孤立色值。
- 区域专属样式集中在 `src/styles.css`；插件或独立页面（如通知中心页）的样式放在对应 `*.css`，但**跨区域的共享元素（侧栏、tab 栏）仍归 `src/styles.css` 管**。

## 会话 Provider

- Codex、Claude、Superbot 必须复用 `ConversationHeader`、`ConversationView` 和 `Composer`，保持标题、消息、执行过程、模型选择和输入区的结构与样式一致。Provider 负责数据适配和能力开关，不另做聊天 UI 或独立配色/尺寸。
- 云端会话通过共享组件的环境标签替代本机工作区，隐藏不支持的附件、权限、工具和后续消息行为；共享 Markdown 渲染不得读取本机文件。

## 侧边栏底部操作行（已归档 / 设置 / 通知中心）

这一类整行入口 + 可选右侧小图标按钮，统一用 **split 结构**：

- 结构：外层 `<div class="...-split">` 包一个主按钮（`...-toggle` / `notification-nav`）+ 可选的右侧小图标按钮（`...-button` / `plugins-toggle`）。右侧小按钮缺省时主按钮加 `solo` 类恢复整行圆角。
- 主按钮一律并入 `styles.css` 的共用组：基础 `display/height/padding/gap/color` 组、导航字号组（`calc(13px + var(--h-navigation-font-offset))`）、dark hover 组、dark color 组。**新增此类入口时把新类名加进这四组，而不是另写。**
- 右侧小图标按钮统一为 32px 方块、左侧 1px 分隔线、右圆角，复用同一组样式。
- 未读计数等角标用主按钮内的 `<b>`，颜色/形状沿用既有规则。

## 顶部主按钮（新会话 split-button）

- 「主按钮 + 右侧提供者切换」用 `new-chat-split` / `new-chat-button` / `new-chat-provider` 这套结构；右侧保持紧凑图标按钮，按 Codex → Claude → Superbot 轮换（Claude 不可用时跳过），不改为下拉框。
- 基色（浅色）与 dark 覆盖必须成对维护：dark 下既要改 `background`/`border-color`，也要显式设 `color`（含 `:hover`），不能只改背景漏掉文字。
- 「新建路由会话」是主按钮与提供者切换之间的图标按钮，同时带 `new-chat-provider new-chat-relay` 两个类：尺寸、边框和深浅主题全部复用 `new-chat-provider`，`new-chat-relay` 只把圆角改为 0。不要为它另写一套颜色。

## 会话 tab 栏（对话 / 待办 + 右侧工具区）

- 右侧工具（铃铛、连接状态等）放进 `.notification-tab-tools` 这个居中容器（`height:40px; align-items:center`），与左侧 `.thread-tabs`（撑满整行居中）对齐。
- 容器内子元素**不要再加 `margin-bottom` 之类的一次性垂直微调**；`connection-state` 自带的下外边距在该容器内已被归零。需要垂直定位时调整容器的 `align-items`，而不是给单个子元素补 margin。

## 右侧路由会话跳转栏

- `RelayDock` 固定在主面板右侧空白列（与快捷 Agent 同一列，位于其上方），只在路由会话或其子会话中出现：路由会话列出子会话，子会话只显示返回路由会话的入口。团队视图和 tab 聚焦模式下隐藏。
- 芯片 `relay-dock-chip` 复用 `quick-action-trigger` 的浅色与深色色板（深色写进同一共用选择器组），状态点直接复用侧栏 `StatusDot`，不另造角标。
- 侧栏中子会话行加 `relay-child`：缩进 + 左侧细引导线，不参与拖拽排序；父会话不在当前列表时子会话回到原位置显示。

## 新会话提示行（工作区 / 项目绑定）

- 提示与紧凑插件入口使用 `fresh-thread-row` 的 flex 换行布局；插件通过 `newThreadPanels` 的 `placement: 'header'` 接入。
- 工作区与项目选择器共用 `fresh-workspace-select`，原生 select 保留键盘操作；项目入口按当前名称占位并限制最大宽度，不能让未选中的长名称撑开布局。
- 文字、图标、hover 背景和边框使用提示行的 `--fresh-control-*` 变量，深浅主题成对定义；项目操作按钮复用同一色板。

## 新增区域时

如果要加一个上文没覆盖的新固定区域，先在本文件补一节约定（结构、共用组、主题要点），再写样式；不要让新区域成为下一个「各自实现」的特例。

## 工作视图与团队主界面

- 统一叫「会话视图 / 团队视图」，定义见 `glossary.md`。两者复用 `navigation/BrandRow.tsx`，点击图标或品牌名切换，使用原生 button 支持键盘和目标视图提示，不增加独立切换控件。
- 两者共用 `.sidebar`、`.brand-row`、`.new-chat-button`、`.thread-row`、`.sidebar-footer` 与 `.main-pane` 样式；团队视图不自建品牌、背景色、选中态或主区外框。侧栏宽度沿用核心导航设置。
- 团队视图保留「工作 / AI 团队」分组、任务筛选及主区详情；专属布局放 `src/features/teams/TeamMode.css`，编辑器与核心服务保持共享。
- 切换隐藏但不卸载已访问界面，不重建会话或运行服务。深浅主题必须一并验证。

## 团队编辑页

- 成员、团队和任务编辑共用居中限宽的分组表单，主体独立滚动、保存栏固定在编辑区底部；团队视图与会话团队 tab 必须一起验证。
- 成员详情以概览、任务、配置、记忆页签承载，未提交的配置和记忆在页签切换时保留。记忆范围切换保留每个范围的草稿与文档版本，预览不触发保存。
- 看板是任务状态的展示入口；开始执行、暂停、停止和验收仍使用领域服务，不通过拖拽直接改状态。

## 通知中心与会话提醒

- 侧栏通知入口打开完整通知中心，列表仅收录允许展示的错误和告警；即时操作反馈显示在当前界面。会话待回应、关注和定时提醒继续使用各自业务状态，不因诊断过滤被删除。
- 桌宠已显示且有活动会话时，通知中心提供“提醒当前会话”设置。到期反馈保留在来源会话，桌宠角标反映待关注状态；已读与处理分开。
- `NotificationViewport` 的右侧浮层和提醒右栏当前未挂载，不恢复旧铃铛、气泡或侧栏入口。修改通知样式集中在 `features/notifications/notifications.css`，深浅主题成对维护；业务边界见 [architecture.md](architecture.md#应用内通知)。

## Router 管理页

- 核心 Router 页签复用既有 thread-tabs 结构与排序，不新增页签专属尺寸或定位；管理页隐藏聊天输入区。
- 页面按「工作区 / 最终 Prompt / 反馈 / 设置」组织，桌面采用工作区列表与详情双列，窄窗口改为上下排列；列表限制高度并可滚动，不让长路径撑宽。
- 页面独立样式放在 features/settings/RouterSettings.css，使用局部主题变量成对覆盖深浅色；设置入口复用同一组件。
- 状态文字与颜色放在工作区标题左侧，路径同行；检查倒计时与更新时间合并，放在更新按钮左侧。详情内只保留介绍、补充说明和保存，不增加说明段落。设置按后端分区，未接入区域整体禁用并置灰；更新、保存和错误均在原区域反馈。

## 输入纠正提示行

- 位于 Composer 输入卡上方，复用输入区宽度并允许窄窗口换行；自动纠正后显示反馈框，不提供单词还原或全局撤回。
- 反馈使用单个“原词 → 替换词”输入框和保存按钮；状态留在本行，不发送会话消息。与 Router 和项目成功卡复用服务端消息接收事件收起；仅加入队列、发送失败或收到模型回复都不触发收起。
- 样式集中在 `features/conversation/inputCorrection.css`，深浅主题成对维护。

## Harness 助理悬浮窗

- 桌宠隐藏时，入口固定在应用右下角，打开应用内浮层；沿用设置弹层的虚化背景与深浅主题，不占用会话或团队视图布局。浮层可拖动，保持在主窗口可视范围；Escape、关闭按钮或点击背景收起后焦点回到入口。
- 桌宠显示时收起应用内入口，单击角色打开 `desktop-assistant` 原生独立窗口。独立窗口复用 `HarnessAssistant` 的 standalone 模式、完整 Composer、主题和字号；关闭或 Escape 只隐藏窗口，执行继续。不把原生窗口拖动和尺寸约束写成应用内浮层行为。
- 桌宠样式集中在 `features/desktop-pet/desktopPet.css`，大肥鱼裁剪参数统一来自共享 `layout.json`，不随动画调整窗口或角标。窗口、权限和素材约定见 [desktop-pet.md](desktop-pet.md)。
