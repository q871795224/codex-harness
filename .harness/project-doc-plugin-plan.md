# 项目文档插件：绑定注入 + 归档按钮改造

> 状态：设计定稿（待实现）。本文固化本轮对齐的结论，作为实现与 review 的依据。
> 背景与协议本体见 [agent-interaction.md](agent-interaction.md) 第七节与 `src/features/project-doc/`。

## 一、要解决的核心问题

项目文档插件目前"绑定了却没反应"。根因是三方职责里 **Harness 的两块缺位**：

| 方 | 职责 | 现状 |
| --- | --- | --- |
| 人怎么用 | 项目 Tab 查看 / 编辑 / 版本历史 / 归档 | ✅ 已实现 |
| Agent 怎么用 | skill 教协议（读 / 写 / CAS / 冲突重读） | ✅ skill 存在，协议正确 |
| Harness · 注入背景 | 新会话选项目 → 文档作为首轮上下文发给 Agent | ❌ **缺失**（绑定只写 UI 状态） |
| Harness · 读写控制 | skill 管 Agent；人可主动把进展归档进文档 | ⚠️ 协议在 Rust 兜底✅；人控按钮❌缺失 |

skill 里"会话绑定项目时，文档正文和文件路径已注入你的初始上下文"这句承诺，代码从未兑现。本次把它做实。

## 二、改动清单

### 1. 首轮注入：输入框第一行的折叠项目背景

新建会话在绑定面板选了项目后，**输入框第一行**出现一个折叠条目（复用现有"粘贴长文折叠"的样式语言），显示**项目名称 + 当前 seq**。

- **不删、直接输入** → 发送这条消息时，把**项目文档正文**展开拼在用户消息前面一起发给 Agent。
- **删掉这个折叠条目** → 该会话不再注入，且**解绑项目**（绑定下拉框同步清空）。"去掉上下文"和"解绑"是同一件事。
- **注入内容 = 仅项目正文**。不带协议、不带 seq 元数据。front matter（`renderProjectDocFrontMatter`）只进落盘文件头，不进注入正文——与现有约定一致。
- 协议由全局 skill 提供（见第 4 点），注入正文不重复携带。

**注入通道**：走"塞输入框草稿"这一唯一允许的注入原语（agent-interaction 不变式 3：回传/注入必须经人审批）。即注入内容是**草稿态可见**的，随用户点发送才进入会话正文，绝不后台自动写入。

**生命周期（方案乙，已定稿）**：

- **语义：一次性，仅第一轮注入**。折叠条目是草稿态 paste，发送第一条消息时被消耗，之后不再注入；后续轮次 Agent 靠已收到的正文记忆。
- **第 0 轮（草稿态，尚未发送任何消息）**：折叠条目 ⇄ 绑定下拉框**双向实时同步**。选中/切换项目 → 条目随之出现或改变；切换成不绑定 → 条目消失；手动删/改条目 → 绑定同步清空。这是唯一的特殊处理窗口。
- **绑定意图持久化**：第 0 轮选项目即保存 `pending` 绑定，供草稿恢复和首轮上下文注入使用。第一条消息发送成功后等待保存 `locked`；若保存失败，提示“消息已发送，但项目绑定锁定失败”，仍消耗已发送草稿，避免重复发送。
- **绑定面板连带改造**：绑定面板和折叠条目是同一份 pending 绑定的两个视图。只有用户编辑导致卡片被删除时才请求解绑；程序同步和发送清空不请求解绑。
- **存储约束**：原生层在 SQLite IMMEDIATE 事务内完成绑定读改写，避免多个窗口/进程覆盖其他会话。只能解除 pending 绑定，locked 绑定不能解绑或换项目；沿用旧 `projectDocThreadBindings` 数据，不从消息标记自动恢复权限。
- **第 1 轮发送后锁死**：绑定关系永久锁定为该项目。此后绑定面板只读，不能切换、不能解绑、不再注入。
- **约束**：不支持在会话中更改项目；每个 thread 最多绑定一个项目（可不绑），绑定后不能更改。

### 2. 「归档到项目」按钮（composer 右侧）

在 composer 行（copy/raw/model 那一行，`composer-actions` 区）新增一个按钮「归档到项目」。**位置通过 `composerActions` slot 注册**——该 slot 已渲染在 `Composer.tsx` 的 `composer-actions` 内，无需改 core 布局。

**行为（匿名会话方案，非主 Agent）**：

1. **预处理**：取最近 N 轮会话（N 可在 config 配，默认 10），过滤工具调用 / 命令等噪声，保留核心对话消息。
2. **模型调用**：起一个匿名 `detached` run，复用快捷 Agent 的 `agentRuns` 能力。模型默认 `gpt-5.6-luna` / `max`，可在插件设置里配。
3. **产出暂存**：run 产出的"提炼后 Status 草稿"**先落插件 storage（持久化），不写文档**。
4. **Prompt 设计**：含当前项目文档正文 + 提炼要求。**不塞任何 skill、不塞 MCP**——归档 run 是独立会话，prompt 自带所需格式说明，不依赖外部 skill。

**结果确认流程（人确认，走编辑通道）**：

5. 点按钮 → 按钮进入 loading 旋转态；run 完成 → **简单通知**（见下）。
6. 点通知 → 跳转到对应项目的**编辑界面**，展示 **Agent 产出 vs 当前 Status** 的 diff（复用现有 `buildLineDiff`：绿增红减）。
7. 人可在编辑界面再改 → 点「保存」→ `writeSection(status, baseSeq=当前seq)` 落盘（带 CAS，冲突则提示）。

**两条写入路径（语义区分，已定稿）**：

| 触发方 | 目标分区 | 写入方式 | 确认 |
| --- | --- | --- | --- |
| **Agent 主动**（`<project-doc-update>` 审批卡） | Log（追加区） | 追加 | 卡片即审批（人难逐字审，只能看卡） |
| **人点归档按钮** | Status（受控区） | 编辑界面 + diff + baseSeq CAS | 人在编辑界面点保存 |

**简单通知（本轮从简，不做统一通知中心）**：右上角持久小通知条（可堆叠、手动关闭、可点击跳转）。归档成功/失败都走它。后续由人单独把全 App 散落的报错/toast 统一到这套机制（**本轮不迁移**，避免 PR 失控）。

### 3. 插件设置界面

通过现有 `PluginSettingsProps` + `saveConfig` 机制，暴露三项可在 config 与设置界面同时修改：

| 配置项 | 类型 | 默认 |
| --- | --- | --- |
| 归档模型 | 下拉 | `gpt-5.6-luna` |
| 推理强度 | 下拉 | `max` |
| 取最近几轮 | 数字 | 10 |
| 归档 Prompt 模板 | textarea | 含占位符的默认值 |

### 3b. 项目编辑面板布局修复

现状 `ProjectEditPanel` 的 textarea 固定 `rows={16}`，只占界面上半部分。改为自适应填满到对话框上方（flex 布局，textarea `flex: 1`），让编辑界面占满可用高度。

### 4. project-doc skill 提升到全局

**问题**：skill 当前是项目级（`.agents/skills/project-doc/`），只在当前仓库开会话时被 Codex daemon 发现。在别的目录开会话，主 Agent 读不到协议 → 审批卡链路（主 Agent 主动写）断掉。

**方案**：把 `project-doc` skill 安装/软链到 **Codex 全局 skill 目录**（`~/.codex/skills/project-doc/`），使任意项目的会话都能读到协议。仓库内文件仍是**单一来源**（协议以仓库版本为准），全局为指向它的软链，保证不同步问题不存在。

**职责边界不变**（agent-interaction 既定分工）：
- skill = 给 Agent 的"说明书"，教协议；
- Harness 核心 = 读写执行与语义正确性（seq CAS、追加落序在 Rust 强制）。

### 5. 支持 Claude 会话

- `supportedProviders: ['codex', 'claude']`，使 Claude 会话也能绑定项目、看到归档按钮与审批卡。
- 归档 run 的 provider 跟随当前会话（`props.provider ?? 'codex'`）。

### 6. 删除「项目看板 Run」

从 `quickActions` 移除「项目看板 Run」注册，使其不再出现在快捷 Agent 面板。Git 历史保留，可回溯。

## 三、明确不做的事

- **归档 run 不读 skill / MCP**：归档 prompt 自带格式说明，独立成立。
- **主 Agent 主动写文档的审批卡通道保留**，不由归档按钮取代。
- **协议语义（seq CAS、追加落序）仍在 Rust 核心**，不依赖模型自觉，不放进插件。
- skill 全局化采用软链而非复制，避免双份漂移。

## 四、验证

- `pnpm build`（改动涉及 UI 与 composer 流程）
- `pnpm test`（前端单测；归档 prompt 过滤逻辑、注入正文拼接补测试）
- 手动核对：新会话绑项目 → 输入框出现折叠背景 → 发送后 Agent 上下文含正文；点归档按钮 → Log 追加一条；删折叠条目 → 解绑且不再注入。
