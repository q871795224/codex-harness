# Codex Harness v0.6.0 验收清单

范围：`v0.5.8..v0.6.0`，共 20 个提交、73 个文件变更。

> 当前 `main`、`v0.6.0` tag 与三个版本文件均为 `0.6.0`。开始验收前先确认测试对象；如果本机 App 显示 `0.6.1`，需记录其 commit，不能默认它等同于本清单对应的构建。

## 改动摘要

| 模块 | 用户可见改动 | 主要风险 |
| --- | --- | --- |
| 会话分支 | 可从指定 turn 创建新会话；新会话显示来源并可跳回 | 历史截断位置错误；误以为文件也被隔离 |
| Agent Activity | 汇总原生子 Agent 的任务、状态、审批数；支持打开和停止 | 状态漏更新、重复事件、停止错会话 |
| 交付入口 | 标题栏可打开 GoLand、复制分支、打开 GitHub PR / GitLab MR 创建页；回复中的文件链接和文件修改项可跳到 GoLand | remote URL 或文件行号解析错误 |
| 快捷 Agent | Job 增加只读、共享写入、隔离交付三种工作区模式；支持停止、结果回传、分支复制、打开及安全清理 worktree | 并发写冲突、worktree/分支误删、重复回传 |
| 终端 | 修复事件对齐和启动状态；改用轻量 shell，xterm 延迟加载 | 无输出、输入过早丢失、切换会话后串流 |
| API Workbench | 修复请求 URL/查询参数和脚本改写请求；增加 10 秒脚本超时与 20 次子请求上限 | 实际发送内容错误、失控脚本拖垮应用 |
| 会话内核 | 拆分启动、生命周期、历史分页、队列、审批、标题和事件解析；修复迟到监听器及 Agent Run 事件竞态 | 创建/恢复、队列、审批等核心能力回归 |
| 构建与安全 | 全量源码覆盖率门禁；设置、Terminal、sandbox 延迟加载；生产/开发 CSP 分离 | 生产包动态模块加载失败 |

## 验收准备

- [ ] 记录 App 版本、commit、macOS 版本、Codex CLI/App Server 版本。
- [ ] 使用一个可安全修改的临时 Git 仓库，并分别准备 GitHub、GitLab 格式的 remote；不要用重要工作区测试清理。
- [ ] 确认 GoLand 已安装；允许 Harness 使用系统通知、剪贴板和打开外部应用。
- [ ] 准备一条普通文本消息、一张图片和一个文件 mention，用于验证结构化输入。
- [ ] 打开应用后确认共享 App Server daemon 正常连接，模型、Skills、MCP 状态能加载。

## P0：核心会话回归

- [ ] 新建会话并发送普通消息；用户消息、流式回复和最终回答顺序正确，无重复内容。
- [ ] 在 active turn 中继续发送一条消息，确认它按服务器能力进入插话或队列；队列状态可见且最终只发送一次。
- [ ] 停止一个包含待处理图片、Skill 或文件 mention 的 turn，再重发保留的输入；附件仍是结构化输入，没有退化成文件名文本。
- [ ] 触发命令审批和文件修改审批；允许、拒绝、取消三条路径都落到正确 turn，卡片不会残留。
- [ ] 关闭再打开 Harness，恢复刚才的会话；历史顺序、标题、工作区、审批状态正确。
- [ ] 对长会话加载更早历史；新旧分页连接处无缺失、倒序或重复，继续发送后消息归属正确。
- [ ] 新建多个会话，验证搜索、重命名、置顶、归档、恢复和批量归档；单个失败不应阻断其余候选项。
- [ ] 切换会话或反复进入/退出页面后再发送消息；同一 App Server 事件只处理一次。

## P1：会话分支与交付

- [ ] 在一段至少三轮的会话中，对中间 turn 点击“从这里分支”。
- [ ] 新会话只包含该 turn 及之前的历史，之后的对话不出现。
- [ ] 新会话继续使用原工作目录；原会话产生的文件修改不会被回滚或复制。
- [ ] 新会话标题栏显示“来自 `<thread-id>`”，点击后能回到来源会话。
- [ ] 点击标题栏 GoLand 入口，确认打开当前会话实际 checkout/worktree。
- [ ] 点击“分支”，确认剪贴板内容与 `git branch --show-current` 一致，并检查“已复制/复制失败”反馈。
- [ ] GitHub remote 下点击“创建 PR”，确认仓库和 source branch 正确，分支名中的 `/` 等字符已编码。
- [ ] GitLab remote 下点击“创建 MR”，确认仓库和 source branch 正确。
- [ ] 对无法识别或没有 remote 的仓库，确认不展示错误的 PR/MR 链接，其他交付动作仍可用。
- [ ] 点击 Codex 回复中的本地文件链接和“修改了 N 个文件”列表，确认 GoLand 打开正确文件；带行号的链接定位到正确行。

## P1：Agent Activity

- [ ] 让当前会话启动两个原生子 Agent；顶部 `Agent Activity` 显示正确总数和运行中数量。
- [ ] 展开后核对每个 Agent 的动作、任务摘要和 running/completed/failed 状态。
- [ ] 子 Agent 产生审批时，待审批数同步更新，审批仍出现在 Harness 统一审批流。
- [ ] 点击某个 Agent 能打开对应子会话，不会跳到另一个 Agent。
- [ ] 停止仍在运行的 Agent，确认只中断目标 Agent 当前 turn，状态最终收敛且不会再次变回 running。
- [ ] 子 Agent 完成、失败以及页面切换后，活动记录均不重复、不丢失。

## P1：快捷 Agent Job

### 配置与启动

- [ ] 在设置中新增 Job，确认可配置名称、prompt、模型、推理强度、运行模式、工作区模式和结果处理。
- [ ] 选择“只读（可并发）”启动两个 Job；二者可并发，实际 sandbox 为只读。
- [ ] 选择“共享写入（互斥）”启动 Job；同一 checkout 再启动写任务时被明确拦截，只读任务仍可启动。
- [ ] 两个写任务几乎同时启动时仍只有一个成功，确认没有竞态绕过互斥。
- [ ] 右下角面板按 Job 和发起会话展示 Run；同一会话可启动多个允许并发的 Run，历史最多显示最近 5 条。
- [ ] active Run 点击停止后变为 cancelled；重复点击或迟到 completion 事件不会把状态改乱。

### 隔离交付

- [ ] 选择“隔离交付（新 worktree）”启动 Job；worktree 位于 `~/.codex-harness/agent-worktrees/<run-id>`，分支和原 checkout 分离。
- [ ] 两个隔离交付 Job 可同时运行，互不覆盖文件。
- [ ] Run 面板能打开正确子会话、在 GoLand 打开对应 worktree，并复制正确分支名。
- [ ] completed/failed/cancelled 后才出现清理入口；运行中的 worktree 不能被清理。
- [ ] 在 worktree 留下未提交改动后尝试清理；操作必须失败，目录和改动保留。
- [ ] 提交或清理改动后再次操作；worktree 目录被安全移除，Git 分支仍保留。

### 手动回传

- [ ] 将 Job 的结果处理设为“完成后可回传当前会话”，从一个现有会话启动并等待完成。
- [ ] 点击回传，父会话收到一次包含 Job 名称、结果和子会话 ID 的结构化结果。
- [ ] 再次回传被拒绝或入口消失，不能产生重复消息。
- [ ] 父会话仍有 active turn 时回传被拒绝；父 turn 完成后可以重试。
- [ ] 从没有父会话的入口启动需要回传的 Job 时，显示明确错误。

## P1：终端

- [ ] 首次打开“终端” Tab，启动期间显示 loading 且不可输入；shell 可用后提示层消失并自动聚焦。
- [ ] 执行 `pwd`、`printf 'ok\n'` 和一条产生多行输出的命令；cwd、输入回显和输出均正确，无乱码或重复。
- [ ] 调整窗口尺寸，确认终端行列同步且内容不重叠。
- [ ] 在两个会话间切换并分别执行命令，确认输出不会串到另一会话。
- [ ] 点击重启，旧 session 正常结束且新 session 可输入；快速切换 Tab 不产生幽灵终端事件。
- [ ] 点击 iTerm2，确认在当前会话目录打开。
- [ ] 在生产构建中首次打开终端，确认延迟加载的 xterm 资源成功加载。

## P2：API Workbench 脚本安全与兼容

- [ ] 请求同时包含原始 URL query 和表格 query 参数，实际发送结果不丢失、不重复。
- [ ] pre-request script 修改 method、URL、header 或 body 后，实际请求采用修改后的值。
- [ ] script 未返回可用 URL 时保留原请求，不发送空地址。
- [ ] pre-request/test script 调用子请求，正常结果能回传给脚本。
- [ ] 单次运行超过 20 个子请求时停止继续发送，并只展示一次清晰的上限错误。
- [ ] 执行超过 10 秒的脚本时终止并展示错误，Workbench 和主界面仍可继续使用。
- [ ] 在生产构建执行一段正常脚本，确认 CSP 保留的 sandbox 能力未被阻断。
