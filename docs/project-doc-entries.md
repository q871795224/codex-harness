# 项目文档条目维护

项目文档继续使用 Markdown。Status 覆盖更新，Log 只追加；Decisions 和 Open Questions 可按条目修改、替代、软删除及恢复。所有保存沿用原有全文版本快照，错误正文和失败经验可以追溯。

## 数据与操作

受管理条目的正文保存在原 Markdown 中，系统注释记录稳定 ID、分区、状态、修订号、原因、替代关系和更新来源；相邻引用段显示状态和原因。Markdown 是唯一正文与属性来源，没有另一份正文数据库。普通段落、列表和代码块仍可使用；条目内部使用三级或更低标题，代码围栏必须闭合。

| 分区 | 操作 | 冲突检查 |
| --- | --- | --- |
| Status | 经人工确认覆盖更新 | 文档 seq |
| Log | 只追加，纠错也追加 | 原生事务定序 |
| Decisions | 新增、修改、替代、撤销、软删除、恢复 | 目标条目 revision |
| Open Questions | 新增、修改、完成、重开、软删除、恢复 | 目标条目 revision |

替代一次完成新决定创建、旧决定状态更新和链接建立。删除只将状态改为软删除，保留正文和原因；恢复回到软删除前的状态。更新正文的旧值留在版本历史。条目修改不会被别的会话追加流水阻挡；同一条目的过期修订会被拒绝，调用者应重读、合并意图再提交。

已有文档不自动拆分或推断决定状态。新增决定和待办自动建立条目；旧段落通过 `adopt` 精确匹配纳管，要求文档 seq、目标分区和完整唯一段落，匹配失败不写入。

## 人工编辑与 Agent 工具

项目 Tab 的“条目”页显示所有受管理记录，包括失效记录。用户可编辑正文、填写原因、选择操作，也可新增或粘贴旧段落纳管。全文 Markdown 编辑继续保留：条目正文可自由修改，Harness 自动推进其 revision；删除系统条目或手工修改 ID/状态等属性会被拒绝，使用“条目”页操作。历史版本恢复是显式整文恢复，仍保留所有已有历史；恢复时重新推进条目修订号，避免旧会话误用曾经有效的修订号覆盖恢复后的内容。

Agent 使用共享的 `project-doc` CLI，不直接写文件。`entries` 读取完整属性；`update`、`supersede`、`delete`、`restore`、`revoke`、`close`、`reopen` 均要求修订号和原因。写入在原生层校验会话绑定，Status 仍沿用原审批流程。CLI 命令细节见 [project-doc Skill](../.agents/skills/project-doc/SKILL.md)。

## 注入与精简

默认仍全文注入。仅当完整正文 token 数严格超过当前作用域插件的门限（默认 10,000），首轮背景才排除受管理的软删除、被替代、撤销条目。Status、Log、未纳管旧段落、有效决定及未软删除的待办（包括已完成）全部保留；附注说明省略数量及完整读取入口。没有相关条目时保持原文。此门限是触发条件，不是截断上限，没有语义检索或模型筛选。

过滤只生成首轮背景，不修改当前文件。项目页和 CLI `read` / `entries` 始终提供完整当前内容。

精简先归档完整原文，再将受管理条目从模型输入剔除；Harness 在提交前从快照原样补回这些条目，保留 ID、正文、状态、原因和修订号。在途追加按既有规则合并；条目被编辑、替代或关闭时，本次精简停止。受管理条目不会被模型重建或压缩，因此以这类条目为主的文档可能无法继续缩短；原文保留并显示未缩短错误。

## 验证范围

原生临时目录/SQLite 测试覆盖条目修订冲突、跨连接追加、原子替代、软删除恢复、待办闭环、全文编辑保护、旧段落纳管、代码围栏和门限边界。HTTP 测试覆盖绑定、修订冲突和完整读取。前端测试覆盖参数传递、原因必填、替代操作和冲突保留草稿；Python CLI 使用本地假 HTTP 服务验证请求和错误行为，不操作真实项目数据。
