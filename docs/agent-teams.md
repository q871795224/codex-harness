# 成员、团队与任务

Harness 支持直接指派一名成员，或把任务交给团队，由队长顺序派发、检查和返工。每次执行保留独立会话，最后由用户验收。

界面沿用现有会话侧栏和 tab。团队 tab 内使用紧凑的左侧列表、右侧详情；任务、成员、团队均在右侧查看或编辑，不展示介绍页或成员卡片。

## 使用流程

1. 打开「团队 → 成员」，创建成员，填写职责、模型、工作区方式。开发成员选择隔离开发，审查成员选择只读。
2. 需要自动协调时，在「团队 → 团队」选择队长与其他成员，填写协作要求。
3. 创建任务，选择具体成员或团队，填写自包含的说明、来源工作区和验收要求。也可从某条回复的成员图标创建，回复正文会填入任务说明。
4. 检查预算并启动。每次队长和成员执行都计入次数预算。
5. 在任务详情查看会话、执行结果和工作区。待验收后选择通过，或填写返工意见再继续。
6. 有可复用经验时，从执行结果选择「编辑后保存」，确认后写入该成员的来源工作区记忆。

## 数据与行为

| 对象 | 行为 |
| --- | --- |
| 成员 | 可加入多个团队；职责、模型和 Skill 选择在任务创建时固定；归档阻止新任务分配，已有任务保留快照 |
| 队长 | 只读协调，不能自选名单外成员，也不能直接标记任务完成 |
| 开发工作区 | 首次写执行创建隔离 worktree，之后同任务沿用；自动调度不执行分支合并 |
| 成员记忆 | 通用和工作区两种范围；每次执行读取所需范围，修改下次生效，冲突不覆盖 |
| Skills / MCP | Codex Skill 来自运行时发现结果，明确选择不等于工具隔离；Claude 不提供 Codex Skill 选择；MCP 沿用共享配置 |
| 暂停 | 停止调度并请求中断成员，可以在检查结果后继续 |
| 停止 | 结束任务的调度，保留记录与工作区 |
| 重启 | 用户确认后接管，未确认的启动状态不自动重放 |
| 预算 | 次数、返工次数与时间窗口；每次重复派给相同成员计返工，用户要求返工同样计数 |

桌面应用必须打开才能继续调度和检查时间预算。关闭应用不停止底层 daemon；已经开始的执行可能继续，重启后先检查已有会话再接管。时间预算不是离线硬截止，执行次数也不是 Token 或费用硬上限。

模型回复和执行正文保留在原生会话，任务文件保存配置、说明、决策理由和关联。成员记忆为可编辑 Markdown，删除内容后下次执行不再读取，但既有会话中的历史不被撤回。结果不会自动重新提炼进记忆。

任务与成员文档采用文件版本检查。发现其他窗口改动时刷新后重试；编辑中的记忆草稿保留，不能静默覆盖。修改预算会明确重新计算时间窗口，次数历史不清零。

模型执行通过依赖注入测试，不依赖真实模型、用户配置或记忆目录。真实模型的队长决策质量需要实际任务验证；结构无效时暂停，不把自然语言猜成派发指令。
